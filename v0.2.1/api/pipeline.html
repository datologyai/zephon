Pipeline¶

The operator chain that turns a curriculum into training batches. The guide covers it in Pipelines: from a curriculum to training batches.

class Pipeline(work_source)¶

Bases: object

Fluent builder that compiles user ops into an executable pipeline.

add_op(op: BaseOp, /, *, name: str | None = None, placement: str = 'auto') → Pipeline[source]¶
add_op(name: str, /, *, process_many: Callable[[list[Any]], list[Any]], preserves_cursor_order: bool, calibration_replayable: bool = False, accumulator: Callable[[...], Accumulator[Any]] | None = None, process_one: Callable[[Any], list[Any]] | None = None, validation_samples: Callable[[], list[SampleRecord]] | None = None, parallelism: int = 1, placement: str = 'auto', indexable: bool = False, batch_shape_sensitive: bool = False, requires_serial_state: bool = False) → Pipeline

Append a custom operator — two forms.

Instance form: pipe.add_op(op, name=..., placement=...). Pass a prebuilt BaseOp subclass instance. Use this when the op needs full lifecycle control — __init__ for configuration, setup for per-worker resource construction (tokenizers, model handles) and OpContext services, traits for any combination of OpTraits fields. The framework deep-copies the instance per parallel worker, so self.* attributes set in setup are isolated per worker on every runner (including the thread runner). This matches the lifecycle built-in operators use. Traits come from op.traits() rather than kwargs.

Kwargs form: pipe.add_op(name, *, process_many=..., ...). preserves_cursor_order is required. Convenience for stateless transforms. The framework builds an internal BaseOp subclass from the supplied callables + accumulator factory + traits. process_many must not carry state between calls; any per-lane or cross-invocation state belongs in the accumulator. Read-only shared resources (codec tables, thresholds) can be captured in a closure over the callables. See the “Accumulators and Operators” page in the documentation for the operator/accumulator split.

Parameters:

  • op – Instance form. The BaseOp instance to attach.

  • name (str | None) – Operator name used in plan graphs, metrics, and logs. The instance form defaults to the class name of op.

  • placement (str) – Placement hint passed to the planner ("auto", "local", or a runner-specific tag).

  • process_many (Callable[[list[Any]], list[Any]] | None) – Kwargs form, required. Callable applied to each ready batch from the accumulator. Receives a list of upstream items, returns the list of downstream items. Runs in parallel workers when parallelism > 1.

  • accumulator (Callable[[...], Accumulator[Any]] | None) –

    Kwargs form. Optional factory returning a fresh Accumulator instance. The framework calls the factory once at runner setup and again on reset_buffers between runs, so a factory (rather than an instance) is required for correctness. Two signatures are supported and auto-detected:

    • Callable[[], Accumulator] — simplest form. Use lambda: CountingAccumulator(max_batch=N) for size-based per-lane batching (it always groups by lane).

    • Callable[*, deterministic, ctx], Accumulator] — for accumulators whose construction depends on the deterministic mode (e.g. enabling latency-based flush only when deterministic is False) or runtime context. Example:

      accumulator=lambda *, deterministic, ctx: (
    CountingAccumulator(
        max_batch=N,
        max_latency_ms=None if deterministic else 3,
    )
)

    Defaults to a PassthroughAccumulator factory — each upstream micro-batch becomes one ready batch as-is.

  • process_one (Callable[[Any], list[Any]] | None) – Kwargs form. Optional fast path for single-element processing. If omitted, the framework wraps each element in a list and routes it through process_many.

  • validation_samples (Callable[[], list[SampleRecord]] | None) – Kwargs form. Optional factory returning a list of SampleRecord instances for the validation harness. Override when process_many requires payload fields beyond the validator’s synthetic {'text': str, 'value': int} — letting the harness run the full op-level + state-diff suite instead of degrading to OP_REJECTS_GENERIC_PAYLOAD. Buggy factories surface OP_VALIDATION_SAMPLES_FACTORY_FAILED and the validator falls back to synthetic records. Include at least two distinct lane_id values so the cross-call-state probe stays meaningful.

  • parallelism (int | None) – Kwargs form. Number of worker invocations to run in parallel for this op. Default 1 (serial). Increase when process_many is CPU/GPU-bound.

  • preserves_cursor_order (bool | None) – Kwargs form, required. True when process_many emits records whose chunk_id order matches their inputs (1:1 maps, payload transforms, non-reordering filters). False when the op reorders, shuffles, or packs. The planner picks a different eviction strategy based on this trait — getting it wrong corrupts checkpoint semantics silently. See the Checkpointing page in the documentation.

  • indexable (bool | None) – Kwargs form. Whether the op preserves indexability through the plan. Default False; set True only if the transform is 1:1 and deterministic.

  • calibration_replayable (bool | None) – Kwargs form. Whether token calibration may replay the op before tokenization. Default False; see OpTraits.

  • batch_shape_sensitive (bool | None) – Kwargs form. Set True when process_many’s output can depend on how inputs are grouped into micro-batches (per-batch RNG, statistics, etc.). In deterministic mode this disables latency-based accumulator flushing for stages containing this op, preserving strong determinism at the cost of some throughput.

  • requires_serial_state (bool | None) – Kwargs form. Set True when the op’s accumulator holds cross-invocation state that cannot be sharded across parallel worker instances. In deterministic mode the planner pins parallelism=1 for ops with this trait.

Returns:

Self for method chaining.

Examples:

# Instance form — class with setup/traits/accumulator overrides.
class Tokenize(BaseOp):
    def __init__(self, name):
        super().__init__()
        self._name = name
        self._tokenizer = None
    def traits(self):
        return OpTraits(
            preserves_cursor_order=True,
            calibration_replayable=True,
            parallelism=4,
        )
    def setup(self, ctx):
        super().setup(ctx)
        self._tokenizer = load_tokenizer(self._name)
    def process_many(self, elems):
        for e in elems:
            e.payload = {"ids": self._tokenizer.encode(e.payload["text"])}
        return elems

pipeline.add_op(Tokenize("gpt2"))

# Kwargs form — stateless windowed transform.
from zephon.ops import CountingAccumulator
pipeline.add_op(
    "windowed_transform",
    process_many=lambda elems: [...],
    accumulator=lambda: CountingAccumulator(max_batch=64),
    parallelism=4,
    preserves_cursor_order=True,
)

ensure_mixture(*, max_buffer_size=1000, drain_target_ratio=0.8, obsolete_drain_rate=0.1, weight_by='auto', warn_tolerance=None, mixture=None, placement='auto', parallelism=None)[source]¶

Enforce mixture ratios using adaptive Smooth Weighted Round Robin.

Place this operator after tokenization (for token-level) or after filtering (for sample-level). The operator automatically detects token fields from common names (input_ids, tokens, token_ids, ids).

Uses adaptive buffering: emit immediately when SWRR’s ideal component is available, buffer when the desired component isn’t present yet. Falls back to emitting best-available when max_buffer_size is reached.

The SWRR algorithm tracks deficit (target - actual) and always picks the component most “owed” samples, ensuring smooth, deterministic convergence.

An end-of-data (EOD) sentinel signals that a component’s source has run out in this lane; buffered records may still arrive. For components listed by WorkSource.continues_after_exhaustion(), this removes their weight from the target, including explicit overrides, and renormalizes the remaining weights. StaticMixtureWorkSource lists components with exhausted_policy="redistribute". Late records follow obsolete_drain_rate in both modes. The final EOD leaves the target unchanged. Previously retired components continue through controlled drainage to avoid a burst of buffered records at final EOD.

Parameters:

  • max_buffer_size (int | None) – Samples to hold while waiting for the component the target mixture needs next. Default 1000; when the buffer fills, the operator emits what it has, so the output mixture may drift if a component stays scarce. Pass None to instead drop the surplus it cannot place on-target — at every epoch boundary and at end of stream. This enforces the mixture at the cost of dropping data. Use strict mode when an exact mixture matters more than keeping every sample. How much is dropped depends on the stream’s skew and on flush_every_k_chunks (smaller → more dropped). ensure_mixture is always non-monotonic, so that cadence defaults to 8; in strict mode the buffer is then discarded on roughly every flush. If drops are too frequent, raise flush_every_k_chunks above the default to give scarce components more time to absorb the buffer (at the cost of holding more in memory between flushes).

  • drain_target_ratio (float) – When forced to emit (buffer hits max_buffer_size), drain the buffer down to this fraction of max_buffer_size before stopping. Default is 0.8 (drain to 80% of max). Ignored when max_buffer_size=None.

  • obsolete_drain_rate (float) – Emit one obsolete record per int(1 / rate) normal output records, regardless of token count. The effective share is 1 / (int(1 / rate) + 1): default 0.1 means one in eleven; values above 0.5 alternate (50%); 0 disables periodic drainage. A record is obsolete if it has any positive off-target contribution or no component in the target. Its on-target contributions still count toward the mixture. At most one slot is saved while the queue is empty. Bounded forced drains and flushes may exceed this rate; strict flushes discard leftovers. Within an epoch, components removed by one target change drain in proportion to their former weights. Separate EODs drain in notice order when their records are available. Other off-target records follow in arrival order.

  • weight_by (Callable[[SampleRecord], float] | Literal['samples', 'auto'] | str) –

    How to compute sample weights. Options:

    • auto (default): Auto-detect token field from common names (input_ids, tokens, token_ids, ids). Raises if not found.

    • samples: Each sample has weight 1.

    • Explicit field name (e.g., input_ids): Use that field’s length.

    • Callable: Custom function taking SampleRecord, returning float. Must not modify the record.

  • warn_tolerance (float | None) – If set, warn when mixture drift exceeds this value (0.05 = ±5%). If None (default), no warnings are emitted.

  • mixture (dict[str, float] | None) – Explicit mixture target {component_name: float}. If None, derived from chunk mixture via engine context. EOD sentinel handling also applies to this override.

  • placement (str) – Placement hint for this operator.

  • parallelism (int | None) – Override default parallelism for this operator.

Returns:

Self for method chaining.

Return type:

Pipeline

Examples

# Token-level (default) - place after tokenize
pipeline.fetch().tokenize(tokenizer_id="gpt2", field="text").ensure_mixture()

# Sample-level enforcement (after filter)
pipeline.fetch().filter(...).ensure_mixture(weight_by="samples")

# With explicit token field
pipeline.fetch().tokenize(tokenizer_id="gpt2", field="text").ensure_mixture(
    weight_by="input_ids"
)

# With warnings for drift (warn if >5% deviation)
pipeline.fetch().tokenize(tokenizer_id="gpt2", field="text").ensure_mixture(
    warn_tolerance=0.05
)

# Explicit mixture target (override chunk mixture)
pipeline.fetch().tokenize(tokenizer_id="gpt2", field="text").ensure_mixture(
    mixture={"English": 0.7, "German": 0.3}
)
expand_chat(*, field='messages', placement='auto', parallelism=None)[source]¶

Emit one conversation prefix per user query containing an assistant.

Each prefix ends before the next user, or at the end of the input. Earlier history and other payload fields are retained. Empty assistant content is allowed. Queries without an assistant emit nothing. Prefixes own independent nested payloads; the sole or final prefix may reuse input objects.

Expansion repeats context and does not select loss targets. Normalize roles before expansion; do not expand data already stored as prefixes. Packed prefixes require document-isolated attention in the model. Keep expansion and tokenization in one stage to avoid serializing repeated history between processes. Changing expansion settings before checkpoint resume is unsupported and is not detected.

Parameters:

  • field (str) – Dot-separated payload path of the messages list.

  • placement (str) – Execution placement, usually shared with tokenization.

  • parallelism (int | None) – Worker count override.

Return type:

pack_flat(max_length, *, num_bins=None, max_sequences_per_bin=None, algorithm='first_fit', tokens_field='auto', pad_token_id=None, emit_positions=True, drop_oversized=None, min_sequence_length=1, shuffle_strategy=None, shuffle_seed=None, flush_strategy='fifo', candidate_pool_size=None, max_candidate_age=None, homogeneity='none', groups=None, placement='auto', parallelism=None)[source]¶

Add a sequence-packing operator that emits flat training records.

Each bin is emitted flat as {tokens_field: concat[+pad], "positions"?} — no packed_samples — so SampleBatch.to_training consumes it directly (positions is surfaced automatically). Uncapped wrap emits only full bins. Capped wrap and the other algorithms pad partial bins, including their final remainder, to max_length with pad_token_id. Buffered algorithms may reorder segments, and best_fit_wrap may emit a suffix before its remaining prefix. When emit_positions=True, positions still reset at every emitted segment; they do not restore source order. Only the token field and length-aligned sliceable fields survive; scalar and non-aligned payload is dropped (use pack_sequences() to keep it).

Parameters:

  • max_length (int) – Fixed length of every emitted record.

  • max_sequences_per_bin (int | None) – Optional positive bound on real segments per output bin, excluding padding. Split fragments count once per bin.

  • num_bins (int | None) – Number of bins to maintain per packing group. Required for first_fit/best_fit and not allowed for wrapping algorithms.

  • algorithm (Literal['first_fit', 'best_fit', 'wrap', 'best_fit_wrap']) – "first_fit" (default), "best_fit", "wrap", or "best_fit_wrap" (candidate-based buffered wrapping with length-based selection and at most one split per bin).

  • tokens_field (str) – Token field to concatenate ("auto" or explicit name).

  • pad_token_id (int | None) – Fill value for the token field when padding partial bins (aligned fields pad with 0). Required for first_fit, best_fit, best_fit_wrap, and capped wrap; unused for uncapped wrap. Any embeddable id works — to_training masks the pad tail from the loss by position (meta.padding_length), not by id.

  • emit_positions (bool) – Include the positions array marking document boundaries (cumsum(positions == 0) - 1 → doc ids). Defaults to True; set False for classic concatenated blocks.

  • drop_oversized (bool | None) – Whether first/best should drop records longer than max_length. Defaults to True for first/best and False for wrap/best_fit_wrap, which split instead.

  • min_sequence_length (int) – Remaining capacity below which a bin is emitted.

  • shuffle_strategy (Literal['random', 'length', None]) – Strategy for ordering sequences before packing.

  • shuffle_seed (int | None) – Seed for random shuffling when shuffle_strategy=”random”.

  • flush_strategy (Literal['fifo', 'fullest']) – “fifo” (default) or “fullest” when num_bins is reached.

  • candidate_pool_size (int | None) – best_fit_wrap only — candidate lookahead per packing group. May be exceeded until the pool contains max_length tokens or reaches the segment cap. Defaults to 1024.

  • max_candidate_age (int | None) – best_fit_wrap only — candidate arrivals before a still-buffered record is force-placed. Defaults to 8 * candidate_pool_size.

  • homogeneity (Literal['none', 'group', 'full']) – If "full", each packed sample stays within a single mixing domain (mixture component); "group" keeps it within a single groups group of domains; "none" (default) mixes freely. See PackSequences.__init__().

  • groups (DomainGroups | Mapping[str, Sequence[str]] | None) – Required for homogeneity="group" — a zephon.ops.DomainGroups or {group: [component, ...]} mapping naming which mixing domains may share a packed sample. Members are mixture-component names (the source’s component_ids), validated against them at build time.

  • placement (str) – Placement strategy for this operator.

  • parallelism (int | None) – Worker count for materializing packed-bin payloads. Bin assignment remains serial, so output is unchanged.

Return type:

prefetch(buffer_size=1024, parallelism=None, *, placement='local')[source]¶

Add a prefetch operator to warm the cache before fetching.

The prefetch operator looks ahead in the sample stream and downloads shards to the local cache before they’re needed by FetchOp. This significantly reduces fetch latency when loading from remote storage (S3, GCS).

The prefetch node is inserted before the fetch node in the pipeline.

Parameters:

  • buffer_size (int) – Number of samples to buffer for lookahead (default: 1024). Larger values provide more prefetch opportunities but use more memory.

  • parallelism (int | None) – Number of concurrent worker threads for downloads (default: 4). Higher values increase download parallelism.

  • placement (str) – Placement hint for the prefetch operator (default: “local”).

Returns:

Self for method chaining.

Return type:

Pipeline

Example

>>> pipeline = (
...     Pipeline(work_source)
...     .prefetch(buffer_size=2048, parallelism=8)
...     .decode_text()
...     .tokenize(field="text")
...     .batch(32)
... )

Note: The fetch operator is automatically added by Pipeline.__init__, so you don’t need to call .fetch() explicitly. The prefetch operator is inserted before the implicit fetch operator.

Note

Prefetch is most effective with: - Remote storage (S3, GCS) with high download latency - Sequential or predictable shard access patterns - Large shards where download time is significant

For local storage or already-cached data, prefetch has minimal benefit.

stateful_transform(name, *, init_state, push, flush=None, should_flush=None, transform=None, placement='auto', parallelism=1, indexable=False, preserves_cursor_order=True)[source]¶

Add a stateful transformation with custom accumulation logic.

This is a higher-level alternative to subclassing BaseOp directly. State management runs on the pump thread (serial); the optional transform runs in parallel workers for expensive computation.

Execution model:

  • push/flush: Run on pump thread (serial) for state management

  • transform: Runs in parallel workers for expensive per-item processing

This split enables patterns like “deduplicate (serial) then encode (parallel)”.

State is partitioned per lane — each lane keeps its own state instance and your callbacks see one lane at a time, so an epoch-boundary flush resets only that lane (required for deterministic replay when one engine owns several lanes). The per-lane lifecycle:

  1. A lane’s state is lazily initialized on its first record via init_state()

  2. push(state, items) is called with one lane’s records -> (new_state, outputs)

  3. If should_flush returns True, that lane’s flush runs and its state resets

  4. On stream end (all lanes) or a lane’s epoch boundary, flush() emits that lane’s remaining buffered items

  5. Each output item goes through transform (if provided) in parallel

Parameters:

  • name (str) – Operator name for debugging/metrics.

  • init_state (Callable[[], _S]) – Factory that creates initial state (called lazily per lane).

  • push (Callable[[_S, list[SampleRecord]], tuple[_S, list[SampleRecord]]]) – Called with (lane_state, one lane’s records) -> (new_state, outputs). Outputs are emitted immediately; state carries forward for that lane.

  • flush (Callable[[_S], list[SampleRecord]] | None) – Optional. Emits a lane’s remaining buffered items at end-of-stream. In non-monotonic pipelines, also called per lane mid-stream at that lane’s epoch boundary; the lane’s state is re-initialized afterward.

  • should_flush (Callable[[_S], bool] | None) – Optional. If returns True, triggers early flush and state reset.

  • transform (Callable[[list[SampleRecord]], list[SampleRecord]] | None) – Optional. Batch-level transform that runs in parallel workers. Receives the full batch from the accumulator, preserving batch structure for efficient GPU processing, vectorized ops, etc.

  • placement (str) – Placement hint for this operator.

  • parallelism (int) – Worker parallelism. Use >1 when transform is expensive.

  • indexable (bool) – Whether this operator preserves indexability (default False). Set True only if the transform is 1:1 and deterministic.

  • preserves_cursor_order (bool) – Whether outputs maintain monotone cursor order. Set False when the transform reorders or packs items (e.g., shuffle, bin-packing). This affects which chunk-eviction path the engine uses for the entire plan.

Returns:

Self for method chaining.

Return type:

Pipeline

Example - Custom batching by token count:
>>> def accumulate_by_tokens(state, items, max_tokens=4096):
...     buffer, token_count = state["buffer"], state["tokens"]
...     outputs = []
...     for item in items:
...         item_tokens = len(item.payload["token_ids"])
...         if token_count + item_tokens > max_tokens and buffer:
...             outputs.extend(buffer)
...             buffer, token_count = [], 0
...         buffer.append(item)
...         token_count += item_tokens
...     return {"buffer": buffer, "tokens": token_count}, outputs
...
>>> pipeline.stateful_transform(
...     "batch_by_tokens",
...     init_state=lambda: {"buffer": [], "tokens": 0},
...     push=lambda s, items: accumulate_by_tokens(s, items),
...     flush=lambda s: s["buffer"] if s["buffer"] else [],
... )
Example - Deduplicate (serial) then batch encode (parallel):
>>> def batch_encode(records):
...     # Process whole batch efficiently (e.g., GPU batching)
...     for r in records:
...         r.payload["encoded"] = encode(r.payload["text"])
...     return records
...
>>> pipeline.stateful_transform(
...     "dedupe_and_encode",
...     init_state=lambda: set(),
...     push=lambda seen, items: (
...         seen | {i.payload["id"] for i in items},
...         [i for i in items if i.payload["id"] not in seen]
...     ),
...     transform=batch_encode,  # processes whole batch in parallel
...     parallelism=8,
... )

tokenize_chat(tokenizer=None, tokenizer_id=None, *, eos_token=None, special_tokens=None, bos_token_id=None, eos_token_id=None, field='messages', max_length=None, chat_template=None, apply_chat_template=True, span_source='auto', supervise_assistant_header=False, loss_scope=None, loss_on_last_turn_only=None, chat_template_kwargs=None, tools_field='tools', enable_thinking_field='enable_thinking', mask_field_out='loss_mask', preserve_upstream_payload=False, placement='auto', parallelism=None)[source]¶

Tokenize each conversation into token IDs and a loss mask.

Reads role/content messages from field (default: messages). Provide a fast Hugging Face tokenizer or tokenizer_id. Uses the tokenizer’s own chat template unless chat_template supplies a template name, Jinja text or a file path. Without an override, a non-None value at tools_field selects tool_use when that template exists, otherwise default. chat_template_kwargs supplies static arguments; tools_field and enable_thinking_field select per-record values.

Output replaces the payload with aligned, unshifted NumPy arrays: input_ids (int64) and loss_mask (uint8; rename via mask_field_out). Ones mark target tokens. preserve_upstream_payload=True retains other fields; max_length truncates the output. Samples with fewer than two tokens or no supervised tokens are dropped.

Targets come from {% generation %} blocks. Untagged templates infer assistant ranges by rendering successive conversation prefixes. Set supervise_assistant_header=True to include assistant headers in those ranges. loss_scope selects all assistant spans (all_assistant, default), the final contiguous supervised run (last_span), all assistant messages after the final user (after_last_user), or every token except the first (all_tokens). Untagged templates require explicit span_source="prefix_diff" with after_last_user.

special_tokens="bos", "eos" or "bos_eos" adds the requested tokens around the complete conversation, reserving room under max_length. "none" adds no tokens beyond those in the input or template. bos_token_id and eos_token_id choose IDs for explicit outer insertion. eos_token overrides the EOS string when loading tokenizer_id.

apply_chat_template=False concatenates message contents without role headers. In this mode, special_tokens="tokenizer_default" uses the tokenizer’s configured special-token processing, and "assistant_eos" appends EOS after each assistant message. With special_tokens omitted, plain conversations use per-assistant EOS; templated conversations get a final EOS if missing and space remains.

With generation tags, after_last_user verifies templates automatically. Each selected assistant’s generation blocks must cover its reasoning, calls, answer and end-of-turn token within its message loop, excluding user/tool-result content. Verification adds rendering and tokenization at setup and for new message/tool formats or non-object tool argument values; successful checks are reused. preflight_tokenizers() runs setup checks before iteration. Samples with omitted selected content are dropped and logged; other verification failures raise. Inspect outputs and masks: checks cannot cover every content-dependent template branch.

loss_on_last_turn_only is deprecated: True selects last_span and False selects all_assistant. Cannot accompany loss_scope.

validate(*, strict=False)[source]¶

Run the custom-op validation harness against the current graph.

Walks every user-supplied operator (those built by add_op()) and runs a smoke test that checks: process_many is stateless across calls, the accumulator conserves samples on push+flush, flush(reset=True) leaves the accumulator in a fresh state, and has_pending_data() mirrors reality. See the zephon.validation module for the full check list and the “Accumulators and Operators” page in the published documentation for the contracts being checked.

Built-in ops are skipped (framework code, tested separately); a graph with no user ops returns an empty report immediately.
