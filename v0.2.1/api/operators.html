Operators¶

The authoring contract for operators you write yourself, and the grouping and lineage helpers they use. The guide covers these in User-defined operators.

Operator authoring kit: the contracts you subclass or pass to add_op().

Built-in operators are configured via the Pipeline builder methods (.shuffle(), .batch(), .tokenize(), …).

class Accumulator[source]¶

Bases: ABC, Generic[T]

Base class for accumulators that run on the pump thread.

Accumulators consume inputs in deterministic order, maintain any cross-invocation state (buffers/bins), and emit ready invocation batches.

Contract for deterministic parallelism: - Operator-owned cross-invocation state must live in the accumulator - Worker process_many must be deterministic given its input batch - Accumulators are invoked only on the pump thread (no concurrent calls)

abstractmethod flush(*, reset=False, lane_id=None)[source]¶

Emit any remaining ready batches.

Called both at upstream close (default, reset=False) and mid-stream by flush sentinels (reset=True). Mid-stream flushes must fully reset internal state so the accumulator is indistinguishable from a freshly constructed instance.

Flush sentinels are injected per lane, so a mid-stream flush is scoped to lane_id: only that lane’s state is emitted and reset, leaving other lanes’ epochs untouched. Flushing every lane at one lane’s epoch boundary corrupts the others and breaks deterministic replay across checkpoint/restore. lane_id=None flushes all lanes (used at upstream close, when every lane is done).

Parameters:

  • reset (bool) – True when triggered by a flush sentinel mid-stream (the accumulator must reset to fresh state), False when called at upstream close.

  • lane_id (int | None) – When set, flush only this lane. When None, flush all lanes.

Returns:

List of remaining batches. These are typically partial batches that were waiting for more elements.

Return type:

list[tuple[list[T], int]]

property reads_payload: bool¶

Whether push_many() may access element payloads.

When True, the runner resolves lazy SHM payloads before calling push_many(). Default False — most accumulators only read metadata (e.g. lane_id).

on_source_exhausted(lane_id, component_id)[source]¶

Handle an end-of-data (EOD) sentinel for a component in this lane.

The component’s source has permanently run out, but buffered records may still arrive, even through order-preserving operators. The default leaves buffers untouched.

Called at most once per component per lane stream; some lanes close without an EOD sentinel. Reactions must be lane-scoped and deterministic for a given input order. Restore reconstructs runner state from replayed sentinels.

Obtain the accumulator-only callback with ctx.get("get_source_exhaustion"). It may be None during validation, which uses an empty context; use SourceExhaustion() (no observed exhaustion) in that case. Otherwise, calling it with lane_id returns a SourceExhaustion snapshot of what this operator has seen: exhausted contains every component whose EOD sentinel reached it, and continuing is the subset the source permits continuing without, per WorkSource.continues_after_exhaustion(). At runtime, the runner updates it before this hook and retains it across epoch resets. It is a cheap local call, available during any accumulator call, including after flush(reset=True). EOD sentinels are emitted regardless of continuation policy. See User-defined operators.

Return ready batches as in push_many(). If dropping records, emit their tombstones with tombstones_for_record() in separate batches from data.

Return type:

list[tuple[list[T], int]]

try_epoch_reset(boundary_chunk_id, lane_id=None)[source]¶

Attempt a delayed epoch reset for stalled flush sentinels.

Called when a flush sentinel was stalled (held behind buffered data) and the runner wants to check whether the accumulator can now be reset.

Returns True if and only if future outputs are equivalent to a fresh accumulator on the retained suffix — i.e., the accumulator’s behavior going forward is indistinguishable from one that was freshly constructed and fed only the records still in the buffer. When returning True, the method must also perform any necessary state reset (e.g., clearing SWRR emission history).

The default implementation is conservative: it returns True only when there is no pending data at all. Accumulators that buffer SampleRecord elements can override this to check chunk_id directly and return True as soon as no pre-boundary records remain, even if post-boundary records are still buffered.

Parameters:

  • boundary_chunk_id (int) – The _boundary_cid from the stalled flush sentinel. Records with chunk_id < boundary_chunk_id are pre-boundary (old epoch).

  • lane_id (int | None) – The stalled sentinel’s lane. When set, only this lane’s buffered records gate the reset; other lanes are independent.

Returns:

True if the reset was performed and the sentinel can be released. False if pre-boundary records still exist in the buffer.

Return type:

bool

class BaseOp[source]¶

Bases: ABC

Base class for operators — both built-in and user-authored.

Attach a subclass to a pipeline via the instance form of zephon.Pipeline.add_op():

pipeline.add_op(MyOp(...))

Built-in operators subclass BaseOp and are attached internally; the same class hierarchy is what user code subclasses for ops that need full lifecycle control (__init__ / setup / traits / accumulator / process_many). The kwargs form of add_op is the lighter alternative for stateless transforms — it wraps user callables in an internal BaseOp subclass, so the same contract documented here applies either way.

Operators are stateless. Instance attributes set in __init__ are read-only configuration or shared resources (a codec table, a threshold, a tokenizer name). process_many must not depend on or mutate state carried across calls — any cross-invocation or per-lane state (buffers, counters, open bins) lives in the operator’s accumulator, not on the op instance. This is the invariant that lets the runtime fan process_many out across parallel workers deterministically.

Fan-out operators must preserve SampleMeta.sample_id and derive child lineage with helpers from zephon.ops.children. This preserves deterministic ordering and replay.

Worker retries do not roll back in-place changes to shared inputs.

Lifecycle: __init__ vs setup¶

__init__ runs once on the user’s main process: store config and lightweight references, and leave runtime fields defaulted to None. The op instance is then deep-copied per parallel worker; on the process and Ray runners it is also cloudpickled across the process boundary, so anything assigned in __init__ must survive cloudpickle on those runners.

setup runs once per worker after the deep copy (and, on cross-process runners, after the cloudpickle round trip). It is the only place to read services from OpContext, construct heavy or non-picklable resources (tokenizers, model handles, open file descriptors), and reset per-worker state. Resources built in setup never need to survive pickling.

The convention in this repo is to construct tokenizers (and similar heavy resources) in setup, not __init__:

class MyOp(BaseOp):
    def __init__(self, tokenizer_name: str):
        super().__init__()
        self._tokenizer_name = tokenizer_name  # picklable config
        self._tokenizer = None  # built per-worker in setup()

    def traits(self) -> OpTraits:
        return OpTraits(
            preserves_cursor_order=True, calibration_replayable=True
        )

    def setup(self, ctx):
        super().setup(ctx)
        self._tokenizer = load_tokenizer(self._tokenizer_name)

    def process_many(self, elems):
        # Records in, records out: rebuild payload, preserve meta.
        for e in elems:
            e.payload = {**e.payload, "ids": self._tokenizer.encode(e.payload["text"])}
        return elems

pipeline.add_op(MyOp("gpt2"))

Defaults supplied:

  • setup records ctx.stage_info as self.stage_info. Overrides should call super().setup(ctx) before initializing worker resources.

  • teardown releases worker resources after processing stops. The default does nothing; resource-owning operators should override it.

  • accumulator — returns PassthroughAccumulator so each upstream micro-batch is forwarded as one ready batch. Override to enable size-based per-lane batching via CountingAccumulator or any custom Accumulator.

  • process_one — wraps the element in a single-item list and routes it through process_many. Override only when the single-element fast path differs (rare).

Abstract — every subclass must implement:

  • process_many — the workhorse transform.

  • traits — must return an OpTraits with preserves_cursor_order declared; the subclass must declare True (1:1 maps, payload transforms, non-reordering filters) or False (reorders, shuffles, packs).

Instantiating a subclass that doesn’t override both process_many and traits raises TypeError at construction time.

validation_samples()[source]¶

Optional records for the validation harness.

Override to opt this op into the validator’s runtime check suite. Returning a small batch (~12 records across a couple of lanes) lets the harness run determinism, cross-call-state, self-mutation, state-diff, sample-identity, and calibration-replay probes against process_many.

Why instance-form ops are gated this way: the validator never invokes setup, so probing a BaseOp subclass whose process_many depends on setup-built resources (the typical pattern — tokenizers, model handles, etc.) would raise spuriously. Returning None (the default) tells the validator to skip the runtime checks for this op and surface a single OP_INSTANCE_RUNTIME_CHECKS_SKIPPED warning instead of crashing the pipeline under auto_validation="strict". Static-AST checks (self-writes, non-deterministic stdlib calls) run unconditionally either way.

Returning an empty list, a list of the wrong type, or raising surfaces an OP_VALIDATION_SAMPLES_FACTORY_FAILED warning and falls back to the skip path — the validator never dies on a buggy factory.

Tip: include at least two distinct lane_id values so the cross-call-state probe (which derives an A-vs-B sample-id variant from your records) and the lane-purity accumulator checks remain meaningful. Records must work without setup having run — pre-tokenize / pre-encode your payload rather than relying on the resources the real setup would build.

Return type:

list[SampleRecord] | None

class CountingAccumulator(max_batch, max_latency_ms=None, *, drop_last=False)[source]¶

Bases: Accumulator[T]

Accumulator that batches elements by count, optionally with time-based flushing.

Elements are routed to per-lane buffers keyed by lane_of(), so each emitted batch is lane-pure. lane_of extracts the lane from whichever element type the accumulator carries (a SampleRecord, or a raw EngineSample tuple at the fetch stage), so the buffer key is always the lane id — which is what lets a per-lane flush sentinel reset one lane alone.

When max_latency_ms is None, this is a pure count-based accumulator suitable for deterministic execution. When set, batches are also flushed after the timeout expires (per lane).

When drop_last is True, flush() discards partial batches instead of emitting them.

class DomainGroups(groups)[source]¶

Bases: object

Groups of mixing-domain (component) names that may share a packed sample.

Members are mixture-component names (the source’s component_ids) — dataset names in StaticMixtureWorkSource, but not necessarily so (a hierarchical source could map several datasets to one component). Validated at construction into an owned map, so mutating the caller’s input afterward can’t change it.

Parameters:

groups (Mapping[str, Sequence[str]]) – Maps a group name to the component names it contains. A component may appear in at most one group. Components absent from every group form their own singleton group.

Example

>>> groups = DomainGroups({"code": ["python", "java"], "web": ["c4"]})
>>> groups.to_member_map()
{'python': 'code', 'java': 'code', 'c4': 'web'}

class OpTraits(*, indexable=True, preserves_cursor_order, calibration_replayable=False, parallelism=1, batch_shape_sensitive=False, requires_serial_state=False)[source]¶

Bases: object

Static capabilities an operator advertises to the planner.

indexable — whether the operator preserves indexability through the plan.

preserves_cursor_order — whether the operator preserves per-lane cursor order (no reordering across chunk/offset/lineage). Required — every operator author must make an explicit True (1:1 maps, payload transforms, non-reordering filters) or False (reorders, shuffles, packs) call.

calibration_replayable — set True if processing each fetched record independently produces the same output payloads and record counts as normal execution, including which records are dropped. Otherwise leave False (default). Output order may differ. The op must also run without accumulators or runner services. Sample IDs are real; lane/chunk positions, component counts, and stage metadata are placeholders and must not affect payloads or drops. Text cleanup, content-based filters, and per-record splits qualify; packing and padding to the longest item in a batch do not. Buffers that only delay or reorder records are safe.

parallelism — suggested parallelism for the operator when not overridden.

batch_shape_sensitive — if True, the operator’s outputs can depend on how inputs are grouped into micro-batches (e.g., per-batch RNG or statistics). In deterministic mode, stages that contain at least one such operator will have time-based flush disabled to preserve strong determinism. When False, ordering determinism suffices and latency flush may be kept for performance.

requires_serial_state — if True, the operator maintains cross-invocation state (e.g., buffers) that must be confined to a single operator instance for determinism. In deterministic mode, operators with this trait will automatically run with parallelism=1. This prevents nondeterministic behavior when multiple worker instances would each maintain separate buffers.

pack_meta(primary_cursor, contributors, *, lane_id, component_sample_counts, component_token_counts=None, tags=None)[source]¶

Build metadata for a packed record that merges multiple contributors.

primary_cursor is the replay identity for the packed record and must be unique per lane. contributors lists all contributors included in the pack; any contributor that completes a base offset must set is_last_child=True.

component_sample_counts aggregates how many original samples from each component are included in this pack. For example, if packing 3 samples from component 0 and 2 from component 1, this would be {0: 3, 1: 2}.

component_token_counts optionally provides token counts per component, computed when packing happens after tokenization. If packing before tokenize, pass None and ensure_mixture will fall back to distributing by sample counts.

Return type:

SampleMeta

spawn_child(parent, child_idx, *, is_last_child=False, tags=None)[source]¶

Create metadata for a child derived from parent.

  • Assigns deterministic child lineage for identity/replay.

  • Contributors:

    • If the parent has no contributors (single-base record), emit one contributor tied to the child cursor and honor is_last_child.

    • If the parent already has contributors (e.g., a child or packed input), preserve their cursors. Only the final child inherits their closing flags; every earlier child gets non-closing refs.

  • is_last_child identifies the final child of this immediate parent. An inherited closing flag is responsibility to complete a base offset, not evidence that it has already been delivered and closed.

  • Raises if you try to spawn a closing child from a tombstone.

Return type:

SampleMeta

Emit a tombstone that marks a base offset complete without payload.

tombstones_for_record(record)[source]¶

Emit tombstone records for every closing contributor in record.

Each record tracks which chunk offsets it contributes to via contribution_refs(). Only refs with is_last_child=True need a tombstone — intermediate children (from split/spawn) don’t close the base offset, so the engine doesn’t need a signal for them.

The string literals that operator-configuration arguments accept.

Which algorithm a packing operator fills its sequences with.

Which special tokens tokenize adds around each sequence.

ChatSpecialTokensMode: Literal[SpecialTokensMode, 'assistant_eos']¶

Which special tokens tokenize_chat adds. assistant_eos appends EOS after each assistant message when no chat template is applied.

MissingFieldMode: Literal['error', 'empty']¶

What tokenize does when a record lacks the field it was given.

SpanSource: Literal['auto', 'generation_tags', 'prefix_diff']¶

How tokenize_chat works out which tokens belong to the assistant.

LossScope: Literal['all_assistant', 'last_span', 'after_last_user', 'all_tokens']¶

Which tokens tokenize_chat supervises. Assistant scopes select spans; all_tokens selects the complete conversation except its first token. Masking the first token prevents packing from turning a conversation boundary into a supervised next-token prediction. after_last_user automatically verifies generation ownership before output.

With generation tags, samples whose selected source content disappears during rendering are dropped and logged at ERROR, counting zero delivered tokens during calibration. Setup failures, wrong ownership and incorrect supervision always raise.

class SourceExhaustion(exhausted=frozenset({}), continuing=frozenset({}), final_component=None)[source]¶

Immutable source facts observed by one operator in one lane.

exhausted contains all components whose end-of-data (EOD) sentinel reached the operator. continuing is the subset listed by continues_after_exhaustion(), whose policy permits continuing without them. The runner updates this snapshot before calling Accumulator.on_source_exhausted().

final_component identifies the EOD that completed exhaustion of all components declared by component_ids() on this lane. It stays None if any declared component is never announced exhausted, even one that emits no records. It does not mean buffered records have drained. A lane may finish without observing a final EOD, so do not wait for it to flush.
