[comment]: <> (### How runners enforce ordering)
[comment]: <> ()
[comment]: <> (When an operator runs with parallelism > 1, multiple workers execute)
[comment]: <> (micro-batches concurrently. Workers may finish in any order, but the runner)
[comment]: <> (must emit results in the original input order.)
[comment]: <> ()
[comment]: <> (In deterministic mode, the runner tags each micro-batch with a monotonically)
[comment]: <> (increasing **sequence number** before dispatching it to a worker. When)
[comment]: <> (results come back, the runner holds out-of-order completions in a buffer and)
[comment]: <> (only forwards them downstream once all preceding sequence numbers have been)
[comment]: <> (emitted. The effect is that the output stream is identical to a)
[comment]: <> (single-threaded execution, regardless of how many workers run in parallel or)
[comment]: <> (how their runtimes vary.)
[comment]: <> ()
[comment]: <> (In non-deterministic mode the runner skips this reordering and forwards)
[comment]: <> (results in completion order instead, trading reproducibility for lower latency.)
[comment]: <> ()
[comment]: <> (### Accumulators: single-threaded state on the pump thread)
[comment]: <> ()
[comment]: <> (Operators like packing, batching, and shuffling need cross-invocation state:)
[comment]: <> (the packer maintains open bins, the batcher fills a buffer, the shuffle)
[comment]: <> (buffer collects elements before permuting them. If this state were spread)
[comment]: <> (across parallel workers, the output would depend on scheduling order.)
[comment]: <> ()
[comment]: <> (Every operator provides an accumulator that runs exclusively on the runner's)
[comment]: <> (**pump thread** --- a single serial thread that receives all upstream elements)
[comment]: <> (in order. The accumulator decides when a batch of elements is ready for)
[comment]: <> (processing and hands it off to the worker pool. Workers execute the stateless)
[comment]: <> (`process_many` call and return results; the pump thread never runs in parallel)
[comment]: <> (with itself.)
[comment]: <> ()
[comment]: <> (Diagram:)
[comment]: <> (Upstream elements -> Pump thread serial accumulator.push_many decides batch)
[comment]: <> (boundaries -> ready batches tagged with seq -> Worker pool parallel stateless)
[comment]: <> (process_many -> results may arrive out of order -> Reorder by seq -> downstream)
[comment]: <> ()
[comment]: <> (Because the accumulator is the only place where cross-invocation state lives,)
[comment]: <> (batch boundaries are identical whether the operator runs with 1 worker or 16.)
[comment]: <> ()
[comment]: <> (### Example: deterministic packing)
[comment]: <> ()
[comment]: <> (Sequence packing is a good example. The PackSequences operator maintains open)
[comment]: <> (bins partially filled sequences and must decide which incoming sequence goes)
[comment]: <> (into which bin. If multiple workers each maintained their own bins, the)
[comment]: <> (assignment would depend on which worker sees which element first --- i.e., on)
[comment]: <> (scheduling timing.)
[comment]: <> ()
[comment]: <> (Instead, all bin state lives in the packing accumulator, which runs on the)
[comment]: <> (pump thread. The accumulator receives elements in stream order, runs first-fit)
[comment]: <> (or best-fit bin assignment single-threadedly, and emits complete packed)
[comment]: <> (sequences as ready batches. Workers only execute the final payload assembly)
[comment]: <> (process_many which is stateless. The bins are also per-lane, so samples from)
[comment]: <> (different lanes are never packed together.)
[comment]: <> ()
[comment]: <> (### Example: data-derived seeds in the shuffle buffer)
[comment]: <> ()
[comment]: <> (The ShuffleBuffer needs randomness, but using a plain incrementing RNG would)
[comment]: <> (tie the shuffle to the order in which micro-batches happen to be formed.)
[comment]: <> (Instead, the shuffle buffer derives its seed from the **data itself**: it)
[comment]: <> (hashes the cursor keys dataset, shard, sample offset, lineage of all elements)
[comment]: <> (in the batch together with a user-provided base seed. The same set of elements)
[comment]: <> (always produces the same permutation, regardless of how they were batched or)
[comment]: <> (on which restart they appear.)
[comment]: <> ()
[comment]: <> (The shuffle buffer uses a CountingAccumulator to collect exactly buffer_size)
[comment]: <> (elements before shuffling, ensuring deterministic batch boundaries. The)
[comment]: <> (data-derived seed then makes the permutation within each batch reproducible.)
